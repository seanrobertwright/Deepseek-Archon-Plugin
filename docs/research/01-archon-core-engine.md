## 1. What Archon (the engine) is — summary

Archon is a self-hostable, governed agentic-automation engine: a Bun/TypeScript runtime that executes **YAML-defined workflow DAGs** mixing deterministic nodes (`bash`/`script` subprocesses), AI-agent nodes (Claude Code, Codex, Pi, Copilot, OpenCode — all through the single session-based `IAgentProvider` contract), human approval gates, durable waits, loops, and governed child runs (`workflow:` sub-runs, data-driven fan-out). Every run is isolated in a git worktree (or, for folder projects, an in-place or hardened container backend), persisted to SQLite (default) or PostgreSQL, and audited through an append-only per-run event log plus a live in-process event emitter. The engine's design posture is "YAML coordinates, code computes, agents judge" (`.archon/workflow-language-constitution.md:9`): the workflow language stays a declarative coordination surface — topology (`depends_on`/layers), gates (`approval:`), retries, loops, artifacts, durable waits, `include:` composition, `workflow:` launches — validated statically at load time, with a deliberately tiny `when:` grammar; all computation lives inside node bodies. Execution is DAG-only (`nodes:`), include-free by the time it runs (`ResolvedWorkflow` + `GraphPlan`), durable-resumable by CAS-guarded run-state transitions and frozen source capture, and observable from outside via (a) the `IWorkflowStore`/`WorkflowDeps` contracts, (b) the singleton `WorkflowEventEmitter`, and (c) exported lifecycle operations in `@archon/core` — the same seams the bundled Web UI uses, so a second UI (e.g. a DSH client plugin) can drive and watch runs without touching server internals.

## 3. The workflow execution model

### 3.1 YAML schema surface (complete as implemented)

**There is no generated workflow-YAML JSON Schema artifact.** The zod schemas in `packages/workflows/src/schemas/*.ts` are the source of truth (the server registers them into OpenAPI via `@hono/zod-openapi`); root `scripts/generate-bundled-schema.ts` only embeds DB DDL.

**Workflow-level fields** — `workflowBaseSchema` (`packages/workflows/src/schemas/workflow.ts:176-264`): `name` (min-1), `description` (min-1), `provider` (trimmed min-1), `model`, `modelReasoningEffort` (deprecated Codex-only alias == `effort` ladder, workflow.ts:33,181), `webSearchMode` (`disabled|cached|live`, :37), `interactive` (bool; run-class declaration "may pause" — gates backgrounding, :203), `effort` (ladder `minimal|low|medium|high|xhigh|max|ultra|persistent` — `packages/paths/src/effort.ts:2-11`), `fallbackModel`, `betas` (non-empty string[]), `sandbox` (SDK-shaped object w/ passthrough, dag-node.ts:86-120), `worktree` `{enabled?}` (workflow.ts:64-73), `container` `{enabled?, write_back?: 'approve'|'auto'}` (workflow.ts:86-105), `evidence_policy` `{required: bool}` (terminal `$ARTIFACTS_DIR/evidence.json` presence gate #2230, workflow.ts:123-126), `mutates_checkout` (default true; `false` skips path-exclusive lock), `persist_sessions` (default for per-node `persist_session`), `tags`, `requires: ['github']` (capability gate), `inputs` (declared signature: record name → `{required?, default?: jsonValue, description?}`, :145-151, :240), `returns` (node id whose output IS the workflow result, :248), `outcome_field` (required boolean property on the `returns:` node — authored verdict mapped `true→succeeded`, `false→failed`, :255), `deprecated` `{message}` (metadata-only notice, :165-168, :263).
`workflowDefinitionSchema` = `z.preprocess(rejectRetiredThinking, base.extend({nodes: z.array(dagNodeSchema)}))` (workflow.ts:276-282) — **every workflow is `nodes:`-based**; `steps:` legacy is a load error (`packages/workflows/src/loader.ts:1356-1361`). `KNOWN_WORKFLOW_KEYS`/`KNOWN_WORKFLOW_NESTED_KEYS` drive unknown-key warnings (workflow.ts:315-366).

**Node common fields** — `dagNodeBaseSchema` (`packages/workflows/src/schemas/dag-node.ts:192-273`): `id` (`INPUTS` reserved, :1192-1198), `description?`, `depends_on?: string[]`, `when?: string`, `trigger_rule?` (`'all_success'|'one_success'|'none_failed_min_one_success'|'all_done'`, :49-54), `model?`, `provider?`, `context?: 'fresh'|'shared'|{resume: nodeId}` (:171-177; `{resume}` agent-only, :1303-1309), `output_format?` (free-form JSON Schema — field-access contract), `allowed_tools?`, `denied_tools?`, `idle_timeout?` (finite positive ms), `retry?` (`{max_attempts 1-5, delay_ms 1000-60000, on_error 'transient'|'all'}` — `retry.ts:6-21`), `hooks?` (strict, keyed by 21 Claude-SDK hook events, `hooks.ts:10-86`), `mcp?` (path to MCP JSON), `skills?: string[]`, `agents?` (record kebab-case-id → `{description, prompt, model?, tools?, disallowedTools?, skills?, maxTurns?}`, :129-137, :212-230), `pi?` (`{enableExtensions?, interactive?, extensionFlags?}` per-node Pi posture, :156-167), `effort?`, `maxBudgetUsd?`, `systemPrompt?`, `fallbackModel?`, `settingSources?: ('project'|'user')[]` (Claude-only), `betas?`, `sandbox?`, `always_run?` (re-run on resume), `mutates_checkout?` (per-node tree-integrity assertion #2771), `persist_session?`, `output_type?` (typed sidecar artifact `nodes/<id>.md` + `<id>.meta.json`).

**Authoring modes → runtime kinds** (YAML has **no `type:` discriminant**; a flat raw schema + superRefine validates exactly-one-mode then transforms; `dag-node.ts:4-11,1106-1963`):

| YAML keyword | kind | notes |
|---|---|---|
| `command: <name>` | `agent` | File-backed AI node (`.archon/commands/<name>.md`, repo→global→bundled); optional `with:` bindings |
| `prompt: <text>` | `agent` | Inline AI node |
| `bash: <script>` | `exec` `runtime:'sh'` | Subprocess; stdout = output; `timeout` ms |
| `script: <inline-or-name>` | `exec` `runtime:'bun'\|'uv'` | Named scripts (`.archon/scripts/`, bundled materialization); `deps` (uv); `with:` → `INPUTS_<UPPER_SNAKE>` env |
| `approval: {...}` | `gate` | Human gate (`message`, optional `decisions`, `capture_response`, deprecated `on_reject`); default decisions `approve`/`reject` |
| `cancel: <reason>` | `halt` | Deterministic stop |
| `wait: {duration_ms \| until \| event+deadline_ms \| attention}` | `wait` | Durable engine-owned wait; fixed output shape |
| `loop: {...}` | `loop` | AI iteration node (owns its provider call) |
| `loop_group: {nodes, ...}` | `loop_group` | Sealed sub-DAG repeated per iteration |
| `include: <name>` (+`with:`) | load-time | Flattened away before execution |
| `workflow: <name>` (+`input`/`with`, `isolation: 'inherit'\|'worktree'`, `fan_out`) | `workflow` | Governed child run (own run row, gates, audit); **target resolved at spawn time** |
| `include:` + `fan_out:` | `compose_fan_out` | Runtime-width composition in the parent run (#2512) |

`fan_out` (on `workflow:`/`include` nodes only): `{items: <$node.output array ref>, as?, max_parallel: int≥1 default 5, join: 'all_success'|'all_done'|'first_success' default 'all_done'}` (:866-873); `first_success` racing is a **load error** (:1504-1515); `as` required on include fan-out (:1516-1523).

The executor-facing `DagNode` union (`dag-node.ts:953-962`) = `AgentNode | ExecNode | GateNode | HaltNode | WaitNode | LoopNode | LoopGroupNode | WorkflowNode | ComposeFanOutNode` (9 kinds — `include` is not a member). `IncludeDirective` (:808-826) exists only pre-expansion. Ignored-field warning tables (`BASH_NODE_AI_FIELDS` etc., :976-1099; `ignoredFieldsForNode` :2020-2037) make AI-fields-on-non-AI-nodes warn, never fail.

**Compact per-kind example** (illustrative):

```yaml
name: my-dag
description: does X
provider: claude
model: sonnet               # tier keyword small|medium|large | @alias | literal
effort: high
interactive: false
mutates_checkout: true
requires: [github]
inputs: {topic: {required: true, description: what}, lang: {default: ts}}
returns: report
outcome_field: ok
evidence_policy: {required: false}
nodes:
  - id: research            # prompt: inline AI agent
    prompt: Research $INPUTS.topic using $ARGUMENTS
    context: fresh
    output_format: {type: object, required: [ok], properties: {ok: {type: boolean}}}
    retry: {max_attempts: 3, on_error: transient}
    skills: [my-skill]
    agents: {helper: {description: d, prompt: p}}
  - id: plan                # command: file-backed AI agent
    command: archon-plan
    depends_on: [research]
    when: $research.output.ok == true
  - id: lint                # bash: deterministic
    bash: 'bun run lint 2>&1 || exit 2'
    timeout: 120000
  - id: check               # script: deterministic
    script: 'echo "{\"status\":\"ok\"}"'
    runtime: bun
  - id: gate                # approval: human gate
    approval: {message: approve the plan?}
    depends_on: [plan]
    when: $plan.output.status == ready
  - id: child               # workflow: governed sub-run
    workflow: archon-assist
    input: $ARGUMENTS
    isolation: worktree
  - id: fanout              # workflow + fan_out: child runs per item
    workflow: per-item
    fan_out: {items: $lint.output.items, as: item, max_parallel: 5, join: all_done}
  - id: block               # include: load-time flatten
    include: review-block
    with: {target: $plan.output}
  - id: iterate             # loop
    loop:
      prompt: refine until done
      until_field: complete       # boolean prop on output_format
      max_iterations: 10
      fresh_context: false
  - id: wait-a-bit           # wait: durable
    wait: {duration_ms: 60000}
  - id: finish
    cancel: done
    depends_on: [iterate, child]
```

### 3.2 Loader & discovery

- **Scopes & override** (low→high): `bundled` < `global` (`~/.archon/workflows/`, auto for every caller) < `project` (`<repo>/.archon/workflows/`); label type `WorkflowSource = 'bundled'|'global'|'project'` (`schemas/workflow.ts:409`). Discovery (`packages/workflows/src/workflow-discovery.ts:617-981`) scans `.archon/workflows/` flat `.yaml|.yml` (max depth 1) **and** packaged `<pack>/<workflow>/` (exactly one YAML) layouts (:168-378). **Overrides are keyed by file name, not by YAML `name:`**; two surviving files with the same `name:` is a hard per-file load error (:740-762). Include/`workflow:` targets resolve by YAML `name:` with 4-tier fuzzy fallback (exact → case-insensitive → `-suffix` → substring; ambiguity throws) — `router.ts:223-262`.
- **Resilience**: per-file read/parse/validation errors are collected into `WorkflowLoadResult.errors`; other files still load (:178-224). Opt-outs via config `defaults.loadDefaultWorkflows`/`loadDefaultCommands`, `commands.folder` (`workflow-discovery.ts:994-1032`).
- **Parse** (`parseWorkflow(content, filename)`, `packages/workflows/src/loader.ts:1308`): YAML (`Bun.YAML.parse`, :128-130) → require name/description/nodes → reject `steps:` → per-node parse (`parseDagNode`) with unknown-key warnings → `validateDagStructure` (:757-1154): unique ids, `depends_on` exist, **Kahn cycle detection**, reserved `INPUTS` id, no `context:'shared'` in parallel layers, every `$node.output` ref resolves (current/enclosing/body scope), `when:` refs valid, no literal whole-AI-output comparison (:963-1015), `fan_out.items` producer is transitive dep, `with:` bindings upstream, loop_group body is a sealed sub-DAG (no `workflow:` inside; wait only as sole terminal sink; recursion :1115-1151) → `validateNodeOutputFormats` (ajv-compile every enforced `output_format`; `workflow:` node may not declare one — the child's `returns:` owns the contract, :1251-1254) → workflow-class placement coercion (:1428-1449) → provider-registered + capability gates (`context.resume` → `sessionFork`; `persist_session` → `sessionResume`) → deprecation handling → `WorkflowDefinition`.
- **Composition** (`expandWorkflowIncludes`, `include-expander.ts:1066`): `include:` flattening renames children `id = <includeId>__<childId>` (`__` is deliberate — dots break the ref grammar, :29-33, :695-830); `depends_on:[I]` maps to child sinks; `$I.output` → `child.returns ?? first sink`; `with:` is substituted at load (`$INPUTS.<name>` in every template surface; missing input = load error); `requires:` unions upward; depth cap `INCLUDE_MAX_DEPTH = 3` (:189). See §3.6 for config travel.
- **Bundled defaults**: generated name→content string maps embedded in `packages/workflows/src/defaults/bundled-defaults.generated.ts` (`BUNDLED_WORKFLOWS` 31, `BUNDLED_COMMANDS` 54 incl. packaged keys, `BUNDLED_SCRIPTS` 12, `BUNDLED_WORKFLOW_OWNERS`), regenerated from `.archon/workflows/defaults`, `.archon/commands/defaults` + packaged dirs (`scripts/generate-bundled-defaults.ts`). `tier-defaults.json` = built-in provider→tier→model presets (claude + codex only).

### 3.3 Graph planning / layers

A `ResolvedWorkflow` = definition (include-free) + `plan: GraphPlan {nodes, layers: readonly DagNode[][], sinks}` (`schemas/workflow.ts:288-304`). `planGraph` (`packages/workflows/src/graph-plan.ts:19-58`) = Kahn in-degree layering (cycle → throw); sinks = nodes never listed in `depends_on`. Execution: `executeDagWorkflow` (`dag-executor.ts:11598`) → `runLayers(ctx)` (:9967-11117):
- A **thunk per node per layer**, run concurrently via `Promise.allSettled` — except a layer containing any `mutates_checkout === false` node runs **fully sequentially** (`settleSequentially`, :9943-9955, :10944-10948) so the git snapshot/assert window is exclusive.
- Per node: prior-success skip on resume (unless `always_run` or a dep re-ran, :10034-10206) → `checkTriggerRule` → `when:` → kind dispatch (`switch(node.kind)`, :10338-10586) → aggregation into `ctx.nodeOutputs`.
- Full independence semantics: same-layer nodes are never cancelled because a sibling failed; every child reaches its own terminal state (constitution §independence-rule). Between layers the executor re-checks the run row and stops unless `running` (`paused` tolerated mid-stream only — `shouldContinueStreamingForStatus` allows `running`/`paused`, aborts otherwise, :984-986, checked every ~10 s inside streams, :2376-2394, and between layers :11074-11108).
- Terminal aggregation (`executeDagWorkflow` :12085-12450): no completed node → fail; any failed → fail listing errors; `evidence_policy` gate; container write-back gate; terminal summary from the child's `returns:` node (typed `summary_value`/`summary_declared_fields`) else the first completed sink; then `workflow_completed` emit + `completeWorkflowRun`.
- Trigger rules (`dag-executor.ts:1949-1986`; default `all_success`): `all_success`, `one_success`, `none_failed_min_one_success`, `all_done` (only pending/running upstreams skipped). Missing upstream treated as failed.

### 3.4 Loops

`loop:`/`loop_group:` control = `loopControlSchema` (`schemas/loop.ts:63-113`): `until?` (prose completion signal; deprecated direction), `until_bash?` (deterministic check, exit 0 completes), `max_iterations` (required, int≥1), `fresh_context` (default false), `interactive?` + `gate_message?` (pause between iterations; `interactive` loop deprecated toward `approval:` gates), `signal_completes?`. Loop adds the third channel `until_field?` (declared **boolean property of the node's `output_format`** — loop-only #2563); at least one channel required (`addMissingChannelIssue`, :130-143). `loop_group` = control + recursive `nodes` (sealed sub-DAG), completion via group `until`/`until_bash` reading body nodes (e.g. `$decide.output.done`).
Runtime (`dag-executor.ts` `executeLoopNode` :5698-7262): one provider stream per iteration, session policy `needsFreshSession = loop.fresh_context || i === 1` (:6053); end-of-iteration completion = OR of `until` prose match, `until_bash` exit 0, `until_field === true` (:6910-7048); events `loop_iteration_started/completed(completionDetected)/failed`. Interactive loops pause with `metadata.approval.type:'interactive_loop'` carrying iteration/session/signaled-output snapshot (:7210-7233); max-iterations exhaustion fails the node. `executeLoopGroupNode` (:4636-5687): body re-executed per iteration by the same `runLayers` with `stepNamePrefix = '<groupId>.'`, per-iteration `nodeOutputs`, `$LOOP_PREV` substitution; group-owned pause cursors (`WaitLoopOwner`, `schemas/workflow-run.ts:66-87`).

### 3.5 Condition evaluation (`when:`)

Grammar is deliberately tiny — **six operators**: `== != <= >= < >` (`when-atom.ts:42`); compounds via `||` then `&&` (no parens, AND binds tighter, short-circuit — `condition-evaluator.ts:300-321`). LHS: `$nodeId.output`, `$nodeId.output.field`, `$nodeId.field` shorthand, `$INPUTS.name`, loop-scoped `$LOOP_PREV.node.output[.field]`; RHS: single-quoted literal (possibly empty) or bare number/`true`/`false` (:75-89). API `evaluateCondition(expr, nodeOutputs, inputs?, {loopPrevOutputs?}): {result, parsed}` (:292-297). **Two failure modes**: unparseable → `{result:false, parsed:false}` → node **skipped** (`node_skipped` reason `when_condition_parse_error`, dag-executor.ts:10256-10295); unresolvable reference (unknown node/field, failed producer, undeclared `$INPUTS`) → **throws → node fails** (never silently false). Whole-text unknown `$node.output` → warn + `''`. Numbers compare via `parseFloat`; `==`/`!=` compare canonical text. `when:` false ⇒ `node_skipped` reason `when_condition` (:10297-10329).

### 3.6 Config travel (workflow-level vs node-level vs run-owned)

`collapseWorkflowScope` (`include-expander.ts:426-440`, invoked per expansion :1243) writes node-affecting fields onto nodes lacking their own value, then **deletes** the workflow-level keys: tuple `NODE_AFFECTING_WORKFLOW_FIELDS = [provider, model, effort, fallbackModel, betas, sandbox, persist_sessions]` (:327-339). `model` travels only when the node's provider equals the workflow's provider. **Run-owned** fields `interactive, worktree, container, evidence_policy, mutates_checkout` never travel; a composed file declaring them warns and drops them (:317-321, :874, :899-936). `requires:` unions upward. `webSearchMode` has no per-node counterpart (named in the load-time warning). Pre-collapse author values are surfaced as `WorkflowWithSource.declared {provider?, model?, effort?}` for display only (`workflow-discovery.ts:797-812`; `schemas/workflow.ts:421-435`).

### 3.7 Sub-runs / child runs / fan-out

- **`workflow:` node** (`dag-executor.ts` `executeWorkflowNode` :7763-8101): invokes an injected `runChildWorkflow` closure (`RunChildWorkflowFn` :881; executor `runChildWorkflow` `executor.ts:1179-1566`) that recursively calls `executeWorkflow` **in-process** for the child, with a runtime cycle guard + depth cap `CHILD_WORKFLOW_DEPTH_CAP = 5` (:1132-1133). Child = separate `workflow_runs` row (`parent_run_id`), own gates/events/cost/audit. Parent re-entry keyed on `metadata.parent_node_id`: no child → start; child completed → thread summary/cost (writes `node_completed` with child_run_id/structuredOutput/declaredFields); failed → resume-through-parent once; cancelled → fail node; paused/running/pending → **pause the parent** (`metadata.approval.type:'child_workflow'` with `childRunId`; no `node_completed`) (:7984-8012). After terminal child states, `maybeResumeParentRun` re-enters a paused parent blocked on that child (`executor.ts:1594-1766`; guard `isRunBlockedOnChild`, `schemas/workflow-run.ts:985-996`). Target resolution is at spawn time (locked behavior — `subrun.test.ts`).
- **Fan-out over child runs** (`executeFanOutWorkflowNode` :8352-8965): `items` resolves to a JSON array at runtime (:8476-8505); empty → completes `'[]'`; re-entry indexes children by `metadata.child_index` (content-hash drift warnings); paused child → cancelled with reason `fan_out_gate` (recoverable); N children via `mapWithLimit(items, max_parallel, …)` (:8774-8836). Join: `all_success` fails on first non-completed child; `all_done` (default) always completes, representing failed children as `{archon_failed: true, error, status}` elements (:8908-8965) — failures as data, judgment downstream.
- **Compose fan-out** (`executeComposeFanOutNode` :9015+, from `include:`+`fan_out:` → `kind:'compose_fan_out'`): per-item **in-parent** expansion via `instantiateResolvedInclude` (`dag-executor.ts:8972-8992`) — one run row, instance-qualified step names, no child rows. Identity is content-addressed: `fan-out-identity.ts:33-51` (`sha256(canonicalValueText(item))` 16-hex + `-k` dupe suffix; scope segment `__archon_fan_out__<nodeId>__<loopIdentity>`); resume keys on a durable ordered instance snapshot (`fan_out_instances` event; never auto-replays ambiguous started-but-unsettled instances).

### 3.9 Command files vs workflows vs scripts

## 4. The AI-provider seam (`@archon/providers`)

### 4.1 Contract
`types.ts:1-3`: the file is the "CONTRACT LAYER — no SDK imports… HARD RULE: This file must never import SDK packages." The whole provider surface is one **session-oriented async-generator interface** (`packages/providers/src/types.ts:804-829`):

```ts
interface IAgentProvider {
  sendQuery(prompt: string, cwd: string, resumeSessionId?: string, options?: SendQueryOptions): AsyncGenerator<MessageChunk>;
  getType(): string;
  getCapabilities(): ProviderCapabilities;
}
```

No chat-completion style, no `abort()` method — abort is signal-based (`AgentRequestOptions.abortSignal`, :491); there is no `executeTask`/`streamEvent` anywhere. `AgentRequestOptions` (:489-520): `model, abortSignal, systemPrompt (string|string[]|preset {type:'preset'; preset:'claude_code'; ...}), outputFormat {type:'json_schema', schema}, env, protectedEnvKeys, maxBudgetUsd, fallbackModel, forkSession, persistSession, nativeTools` (:534-539 in-process tool `{name, description, inputSchema, handler}`). `SendQueryOptions` (:622-637) adds `nodeConfig (raw YAML node bag), assistantConfig (assistants.<id> defaults), execContext ({kind:'host'}|{kind:'container', containerId, execUser?})`. `NodeConfig` (:545-615): `nodeId, mcp, hooks, skills, agents, allowed_tools, denied_tools, pi, effort, sandbox, betas, output_format, maxBudgetUsd, systemPrompt, fallbackModel, settingSources, idle_timeout` + index signature. Container/overlay contracts (`ExecutionContext`, write-back shapes, `CONTAINER_ENV_DENYLIST`) also live here so both isolation (producer) and workflows (consumer) can import them.

### 4.2 Capabilities (single source of truth)
`ProviderCapabilities` (`types.ts:643-708`): `sessionResume, sessionFork?, mcp, hooks, skills, agents, toolRestrictions, knownToolNames?, renamedTools?, structuredOutput: 'enforced'|'best-effort'|false, envInjection, costControl, effortControl, fallbackModel, sandbox, settingSources, nativeTools, containerExec`. Examples: Claude `sessionResume+sessionFork+mcp+hooks+skills+agents+toolRestrictions:true, structuredOutput:'enforced', nativeTools:true, containerExec:true`; Codex `structuredOutput:'enforced', effortControl:true` but `skills/agents/hooks:false, containerExec:false, toolRestrictions:false`; Pi `structuredOutput:'best-effort', sessionFork:true, mcp:false`. dag-executor warns on mismatches and fails fast on hard requirements (e.g. `containerExec:false` refuses a container run).

### 4.3 Registry & model resolution
`registry.ts` = module `Map<string, ProviderRegistration>` (:37); `ProviderRegistration {id, displayName, factory: () => IAgentProvider, capabilities, builtIn, credentials, parseRunConfig}` (`types.ts:755-785`). API: `registerProvider` (throws on duplicate or `sessionFork` without `sessionResume`, :39-55), `getAgentProvider(id)` → `factory()` instantiation + `UnknownProviderError` (:61-68), `getRegistration`, `getProviderCapabilities(id)` (:86), `parseProviderRunModel`, `getRegisteredProviders`, `getProviderInfoList` (API-safe; attaches `EFFORT_LADDER` when `effortControl`), `isRegisteredProvider`, `registerBuiltinProviders()` (:130-179: claude, codex), `registerCommunityProviders()` (:201-205: opencode, pi, copilot — each idempotent), `clearRegistry()`. ### 4.4 Streaming (`MessageChunk`)
Single streamed union `MessageChunk` (`types.ts:238-369`): `assistant {content, flush?}`, `system`, `thinking`, `result {sessionId?, tokens?, structuredOutput?, isError?, errorSubtype?, errors?, cost?, stopReason?, numTurns?, resolvedModel?, resumed?}` (:251-274), `rate_limit`, `tool {toolName, toolInput?, toolCallId?}` (:277), `tool_result {toolOutput, toolCallId?, toolOutcome: 'success'|'error'|'interrupted'|'unknown', exitCode?}` (:287), subagent-task `task_started|task_progress|task_notification` (:313-338), `background_tasks` (full-set replace; dag-executor gates node completion on an empty set, :339-349), `hook_started|hook_response` (:355-368), `workflow_dispatch` (:369). **Session ids ride on `result.sessionId`**; there is no `session_id`/`text`/`retract` vocabulary (retract doesn't exist; providers emit cumulative deltas the executor joins). `result.resumed` (true/false/absent) is stamped centrally (`shared/resumed.ts:17-45`).
Per-SDK: Claude wraps the **Claude Agent SDK** `query()` (always spawns the CLI subprocess; `claude/provider.ts:944-1279` normalizes `assistant`/`system`/`tool_use`/`task_*`/`background_tasks_changed`/`hook_*`/`result` messages; tool results captured via `PostToolUse`/`PostToolUseFailure` hooks drained between events :878-970; synthetic `<synthetic>` error prose withheld and rethrown as `ClaudeApiResultError` :987-998,1167-1199; first-event hang timeout 60 s). Codex (`@openai/codex-sdk`, `codex/provider.ts:459-836`): thread ids from `thread.started` → `result.sessionId`; `agent_message`/`command_execution`/`reasoning`/`web_search`/`mcp_tool_call` items mapped; inline-JSON structured output parsed at `turn.completed`. OpenCode drives an **embedded in-process HTTP server** (`community/opencode/runtime.ts:156-159`, ref-counted, random port + password; external baseUrl mode rejected).

### 4.5 Structured output
`shared/structured-output.ts`: best-effort providers get prompt augmentation + transcript parsing (3-tier parser incl. `jsonrepair`, :68-121); enforced providers grammar-constrain natively but still run a post-parse **ajv v8** net (`compileOutputSchema` load-time — an unenforceable contract fails before spend, :293-301; `validateStructuredOutput` → `StructuredValidationResult`, :308-366). OpenAI strict mode requires `normalizeJsonSchemaForOpenAiStrict` (recursive `additionalProperties:false`, :147-233). Re-ask on miss: ≤3× best-effort, fail-fast enforced (:11-21).

### 4.6 Credentials / OAuth
Delivery is owned by `@archon/core/credentials`; providers declare the consumption matrix: `CredentialKind = 'api_key'|'subscription'|'ambient'` (:720-721); registry `credentials`: claude→anthropic `[api_key, subscription]`, codex→openai `[api_key, subscription]`, copilot→github-copilot, pi→generated from installed SDK, opencode→**dynamic** (models.dev introspection). OAuth (`packages/providers/src/oauth.ts`): wraps Pi's SDK OAuth utilities — `OAuthProviderInterface {id, usesCallbackServer?, login, refreshToken, getApiKey}` (:105-114); singletons `anthropicOAuthProvider` (callback server) / `githubCopilotOAuthProvider` (device flow) (:199-208); `getOAuthProvider('openai')` deliberately undefined (the Codex PKCE flow lives in core — needs the `id_token`; :210-226); auto-refresh `getOAuthApiKey`/`mintOAuthApiKey` on `Date.now() >= expires` (:249-279). Per-provider env: Claude mirrors `CLAUDE_API_KEY→ANTHROPIC_API_KEY` only when no explicit key/OAuth token exists (`claude/provider.ts:169-223`); Codex subscriptions ride a CODEX_HOME `auth.json`; Pi via env-map + per-run `auth.json` (`ARCHON_PI_AUTH_PATH`); Copilot requires `COPILOT_GITHUB_TOKEN` (generic GH tokens ignored). ### 4.7 Binary resolution & container exec
Claude/Codex/Copilot SDKs always spawn native CLI subprocesses; in **compiled** binaries the SDK's own binary discovery breaks, so each provider ships a resolver: env (`CLAUDE_BIN_PATH`/`CODEX_BIN_PATH`) → config (`claudeBinaryPath`/`codexBinaryPath`) → autodetect/vendor → throw with install instructions (`claude/binary-resolver.ts:149-215`; `codex/binary-resolver.ts:138-197`); in dev (`BUNDLED_IS_BINARY=false`) returns undefined and the SDK uses its bundled binary. There is no `useBinary` knob. Claude-in-container runs through a `spawnClaudeCodeProcess` hook that runs `docker exec -i` with denylisted env and a pidfile shell wrapper, overriding `kill()` to signal the in-container pid (`claude/container-spawn.ts:73-119`); only Claude declares `containerExec:true`. Pi is in-process (SDK), needs a package-dir shim in compiled builds; OpenCode is embedded-server.

### 4.8 Skills / MCP node scoping
Policy: workflow AI nodes start with **no** ambient skills/plugins/MCP; only what a node explicitly names loads (AGENTS.md). Claude is the strict implementation: `skills = nodeConfig.skills ?? []`, `strictMcpConfig = true`, an "installed-but-unreachable" named skill **throws before spend** (`claude/provider.ts:493-557`); `mcp:` path → JSON → `mcpServers` + `mcp__<name>__*` wildcards (:612-617); in-process `nativeTools` register as an MCP server named `archon` (`claude/native-tools.ts:14,70-87`). Codex suppresses its automatic skill catalog for workflow nodes (`config.skills = {include_instructions:false}`, `codex/provider.ts:252-271`); Pi restricts to its 7 built-in tools; Copilot defaults `enableConfigDiscovery:false` so repo `.copilot/` never implicitly loads.

### 5.4 WorktreeProvider
- **Branch naming** (`generateBranchName`, worktree.ts:594-618): issue → `archon/issue-<id>`; PR non-fork → the real `prBranch` verbatim (pushes to the PR); fork → `archon/pr-<id>-review`; review → `archon/review-<id>`; thread → `archon/thread-<sha256-hex-8>`; task → explicit/existing branch or `archon/task-<slugify, ≤50 chars>`.

Fork PR: fetch `pull/<n>/head` and `checkout -b` the review branch; same-repo PR: fetch + `worktree add -b <prBranch> <remote>/<prBranch>` + set-upstream. ### 8.1 Connection & dialects
`db/connection.ts`: `getDatabase()` singleton (:44-73) — **`DATABASE_URL` set → `PostgresAdapter`; else SQLite at `<ARCHON_HOME>/archon.db`** (`getSqliteDbPath` :36-38). `getDialect()`, `getDatabaseType()`, `getDbNotificationListener()` (PG LISTEN/NOTIFY only), `closeDatabase`, `resetDatabase`. Adapter interface (`db/adapters/types.ts`): `IDatabase = {query<T>(sql, params?), withTransaction<T>(fn), close(), dialect, sql: SqlDialect}`; `DbNotificationListener.listen(channel, onNotify, onError)`; `WORKFLOW_EVENT_NOTIFY_CHANNEL = 'archon_dashboard_event'` (:63). `SqlDialect` (:89-126): `generateUuid, now, jsonMerge(column,paramIndex), jsonArrayContains, nowMinusDays, daysSince`.
- **SQLite** (`adapters/sqlite.ts`): `bun:sqlite`; PRAGMAs `journal_mode=WAL`, `busy_timeout=5000`, `foreign_keys=ON`; `query` converts `$N→?` and reorders params, **strips `::jsonb` and `::INTERVAL` casts** (`convertPlaceholders` :183-200); transactions serialized on a module queue (`txTail` :107-133). Dialect helpers `sqliteDialect` (:885-913): `now() = datetime('now')`, `jsonMerge = json_patch(col, $N)`, `jsonArrayContains = instr(json_extract(...), $N) > 0`. - **PostgreSQL** (`adapters/postgres.ts`): `pg.Pool(max:10)`; one-time `schemaInitPromise` (:48-66) inside `pg_advisory_xact_lock(1796)` runs **the whole combined migration** `getSchemaSQL()` idempotently, then best-effort (lock 1797) installs the **NOTIFY trigger** `archon_notify_workflow_event` → `pg_notify('archon_dashboard_event', NEW.workflow_run_id)` per insert (:19-30, :156-181). Dialect `postgresDialect`: `jsonMerge = col || $N::jsonb`, `jsonArrayContains = col->'path' ? $N`. Cross-process wake-ups consumed by the server dashboard poller and core `waitForRunAttention`.
**Dual-dialect mechanism in full**: SQL is written once with PostgreSQL `$N` placeholders + PG JSON operators; the SQLite adapter rewrites placeholders and strips PG casts; dialect differences (JSON merge/extract, now, dates) are handled by (a) `SqlDialect` helper methods called from SQL builders and (b) explicit `getDatabaseType()==='postgresql'` branches for PG-only SQL (row locks `rowLockClause` `db/workflows.ts:114-116`; JSON extract expressions :159-203).
